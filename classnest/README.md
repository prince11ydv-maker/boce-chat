## Open locally

Install Node.js 24 LTS. Double-click START-WEBSITE.cmd and open http://localhost:3000, or run:

```powershell
npm.cmd ci
npm.cmd start
```

Keep the terminal open. A new installation offers **Set up workspace** to create an owner account. No default password is shipped. Existing installations retain accounts and data; preserve their data/ directory.

## Everyday use

Approved accounts are required for class content. Pending accounts see an awaiting-approval screen; blocked accounts see a contact-administrator screen. Both retain their own account settings, help, status refresh, and sign-out controls, but receive no notes, notices, routines, discussions, files, or teaching data—even in their requested semester. Registering another unapproved account therefore does not open another class.

- **Mobile app:** install the website as an Android/iPhone home-screen app, or use the signed Android APK in [MOBILE.md](MOBILE.md). Header controls wrap on narrow screens. Class content requires internet and sign-in. In-app and verified, opted-in email alerts continue alongside the new phone-alert channel.
- **Sign-in and semester privacy:** guests see a login/signup gateway and public help, not class subjects, notes, notices, routines, or discussions. Students stay in their administrator-assigned semester; the selector is locked and server checks reject other-semester content, files, and mutations. Approved teachers use saved teaching choices plus active administrator-assigned semesters, falling back to their primary semester when no choices exist. Administrators manage all semesters. Account changes, logout, and reduced teacher scope clear stale views and previews.
- **Appearance:** choose **Light**, **Dark**, or **System**. System follows your device's appearance and responds when it changes. Your choice is saved in this browser and stays in sync across its Classnest tabs.
- **Nepal clock:** the homepage shows the current time, including seconds, above its date. Both use Asia/Kathmandu; the clock does not announce every second to screen readers.
- **Student / Teacher / Admin sign-in:** choose the matching portal. Students choose their current semester; teacher applicants can check one or more teaching semesters. Both account types wait for administrator approval before class content or contributions are available. Choosing Teacher or checking semesters never grants teacher permission by itself. Existing accounts and passwords are retained; owners use the Admin portal.
- **Teacher semester profile:** open **Teacher dashboard → Choose semesters** to save one or more teaching semesters. These choices set the library/dashboard scope; they do not approve the account, change primary membership, create assignments, or grant private discussion/notification access. Active assigned semesters remain available even when unselected. Existing teachers without choices start from their primary semester.
- **Teacher dashboard:** approved teachers see their own classes today, unanswered upcoming classes, the next 48 hours, weekly assignments, and shared notes. Use **All my semesters** or an individual semester to focus the view. Class scope combines saved choices with actual assignments; the notes panel shows only that teacher's contributions, including notes from other semesters. The latest 200 matching note records are listed, with a notice when more exist. **Share notes** lets the teacher choose a subject in the intended semester; opening an existing note for editing loads that note's semester and text.
- **Teacher setup:** approve legitimate teacher requests in Manage workspace, then open **Teaching & my notes → Teacher timetable → Assign a class**. Choose the teacher, subject, weekday, 24-hour Nepal start/end times, and optional room. The imported weekly PDF grid does not identify teacher accounts, so reminders need these explicit assignments. No teacher accounts, addresses, or mappings are invented.
- **Daily timetable:** it appears before the weekly class routine. Administrators choose a date and publish structured subject/teacher/time/room rows, or prefill from that day's teacher assignments. Publishing an empty day marks it as having no classes. A published daily plan replaces weekly teacher assignments for that date and creates account alerts for approved recipients in that semester. Dates can be viewed from seven days ago through thirty days ahead; daily plans and class occurrences are retained for 35 days.
- **Class reminders and teacher replies:** approved students receive a reminder for their own semester's scheduled class, targeted three minutes before its start; the assigned teacher receives their reminder too. Teacher replies open 24 hours before class and close when it ends: **Coming** with **1–5**, **5–10**, or **10+ minutes**, or **Not coming** with a reason. Authorized signed-in class views show attendance status; explanations stay in authorized views/private notifications. The one-minute worker targets this window; polling, network, browser, and provider delays affect actual arrival.
- **Notifications:** approved accounts see notes, notices, daily plans, class reminders, and teacher updates. Students receive their own semester's updates; teachers retain primary/actually assigned private-notification scope. Notice publication creates scoped alerts atomically, excluding the author. **Open update** opens that exact update after authorized sign-in. Open pages refresh account alerts about every 60 seconds; email still requires verification and opt-in.
- **Phone alerts:** open **Notifications → Enable phone alerts** and grant permission yourself. Web Push works in compatible browsers/PWAs. iPhone/iPad requires iOS/iPadOS 16.4 or later and Safari **Add to Home Screen**. Android 1.1.1 uses its app menu and Google Play Services with the configured Firebase channel. Lock-screen text is generic; clicks resolve an opaque notification ID after sign-in. Nothing prompts or subscribes on page load. Logout/session expiry ends that device binding; sign in and enable again. See [HOSTING.md](HOSTING.md) for configured Web Push and native Android setup.
- **Manage workspace → Edit name & current semester:** choose the workspace default. Students remain assigned to their own semester; teachers see selected/assigned library scopes and administrators choose any semester. Browsing never changes account membership.
- **Homepage → Class routine / Exam routine:** administrators edit either table for the selected semester, from the homepage or Manage workspace. Add/remove rows and columns, edit cells, and choose **Publish routine**. Limits are 12 columns, 40 rows, 160 characters per cell, and 80 per heading/title. Saved changes appear to authorized semester accounts. Exam routines stay empty until published; clear rows and publish to make a section empty again.
- **Routine edits:** if another administrator tab has saved a newer revision, the server rejects an outdated save. Your draft stays in the editor; choose **Discard draft & load published version** when you are ready to reload it.
- **Import a table:** in either routine editor, open **Import HTML table**, paste your `<table>…</table>` code, and choose **Preview table**. Select a table when the code contains several, and turn off the first-row heading option if needed. **Use this table in draft** replaces the editable headings and rows; the title stays unchanged. Check the grid and choose **Publish routine** to show it on the homepage. Merged cells are expanded by repeating their text. Only plain cell text is kept; scripts, links, and styling are discarded. HTML input is limited to 256 KiB and the usual routine size limits apply.
- **Subject library → New subject:** create folders with course codes, descriptions, and colors. Admins can edit or delete folders; deleting a folder also removes its notes and attachments after confirmation.
- **Share a note:** approved students contribute in their assigned semester; approved teachers use selected/assigned scopes and administrators manage all semesters. Write text or attach PDF, Office, text/Markdown, or supported images. Files are limited to 20 MiB each and share a 700 MiB note/notice allowance. Reading, previews, and downloads require an authorized signed-in account. Admins and authors can delete notes within their access. **My notes** lets authors edit title, subject, and text; editing retains the attachment.
- **View a note:** choose **View** or open its title to preview PDF, PNG/JPG/WebP, text, or Markdown attachments inside Classnest. PDF previews include pages, zoom, and a page-text option. Long text previews show the first 1 MiB. Office files and unsupported previews retain the download option. PDF.js assets are served by Classnest; no Google/Microsoft viewer or file-sharing link is used.
- **Notice board:** approved teachers and administrators publish to a semester in their allowed scope. Teachers edit/delete their own notices; admins manage all and can pin them. Creation notifies approved recipients in that semester. Edits preserve semester/attachment and do not rebroadcast. A notice needs a title and text, one photo/PDF, or both. Supported originals and existing preview/file limits remain unchanged. Direct notice links focus the exact card after authorized sign-in.
- **Notice photos and previews:** originals can be up to 100 megapixels and 30,000 pixels per side. Supported browser-native photo previews are limited to 16 megapixels and 12,000 pixels per side. HEIC/HEIF/TIFF and larger photos keep a download option. PDF previews use the existing in-app page/zoom controls. The website does not send documents to an outside viewer.
- **Schedule & deadlines:** admins add classes, exams, events, and deadlines in Nepal time. Authorized signed-in viewers can export an event to a calendar.
- **Join your class:** choose your current semester before entering your name, email, and password. Registration requires a valid semester. New accounts wait for administrator approval.
- **Discussions:** approved members read, start, and reply in their primary account semester. Teacher profile choices do not grant other private discussions. Administrators moderate all semesters; authors can delete their own discussions while they retain access.
- **Class members:** approve, revoke, or block posting access and update each account's semester. Check the assignment before approving a student. Existing accounts are assigned the current workspace semester during this update: Semester 3 for this workspace. Existing passwords, sessions, and shared content are preserved.
- **Account:** view your primary semester. Ask an administrator to correct/advance it. Teacher library/dashboard choices are separate from primary private membership. Selectors, dashboard filters, and email preferences never change membership. Email verification does not replace administrator approval.
- **Saved notes:** hearts bookmark notes in the current browser. Bookmarks do not sync between devices.
- **Account → Change password:** change your password and sign out other sessions. Do not share administrator credentials.
- **Sign in → Forgot password?:** request a private, single-use reset link. It expires after 30 minutes; completing the reset signs out old sessions and returns you to ordinary sign-in.
- **WhatsApp support:** open [WhatsApp · +977 9763214754](https://wa.me/9779763214754) from the footer, account/help screens, recovery forms, or Android 1.1.1 menu. The link only opens WhatsApp; you choose whether to send a message. No account details or message are sent automatically.
- **Sign in → Request admin help:** use this fallback if reset email is unavailable. Enter the account email and an optional message of up to 500 characters. The response is generic and never confirms whether an account exists. Do not include passwords, verification codes, or keys.
- **Manage workspace → Password help requests:** administrators verify identity independently before setting a temporary password. Verification and reset each require the administrator’s current password; the same administrator must finish within 30 minutes. A temporary password expires after 24 hours, revokes old sessions, and requires a new personal password before class or admin tools open. Role, semester, approval and email preferences are preserved; pending/blocked accounts stay restricted. Self-service password changes use Account → Change password.
- **Account → Email preferences:** verify your email and opt in to new notes, notices, or schedule/daily/attendance updates. Student emails follow the account's assigned semester. Approved teachers can separately enable their teaching-reminder emails. All categories start off; approval and verified email are required and checked again before delivery. Each notification includes a link to stop emails without signing in.
- **Help & FAQs:** public help covers accounts, plans, notifications, routines, previews, semester-restricted notes, registration, private discussions, uploads, email, themes, and bookmarks. The responsive footer includes Prince Kumar Yadav’s copyright, primary WhatsApp support at +977 9763214754, a secondary contact email, and the FAQ link, without exposing class content.

Create any subjects and semesters you need. No guessed syllabus, fabricated course notes, or university notices are shipped.

## Backups and recovery

**Manage workspace → Download database backup** exports a local SQLite snapshot or cloud portable JSON. It includes personal information and password hashes: keep it private. Attachments are separate. Copy local data/uploads/ or back up the private Supabase bucket, and keep copies off the server.

Current portable-v1 exports contain fifteen durable tables, adding notice attachment metadata to routines, teacher assignments, daily plans, class occurrences, and teacher semester-profile choices. Older nine-, ten-, thirteen-, and fourteen-table exports are accepted and gain empty optional collections; old user records default to student account type unless their role is teacher. Account IDs and password hashes are preserved. Portable exports exclude sessions, app-notification inboxes, notice upload markers, email tokens, email preferences, queue contents, password-help requests/verification notes, and secrets. Temporary account hashes retain their forced-change marker and expiry when exported/imported. They contain attachment metadata, not file bytes: back up both note and notice files separately. Imports require an empty target and reject a filename shared by a note and a notice. Class occurrences include teacher replies and reasons, so keep backups private.

To restore SQLite, stop the application first, preserve the current directory, and restore the snapshot as data/classnest.sqlite with matching uploads. Do not reuse stale WAL/SHM files from a different database. Never replace a running database. Cloud imports refuse occupied targets; use a new database for recovery and verify it before switching the runtime connection.

Local SQLite mode supports one server. PostgreSQL/Supabase mode uses shared locks, sessions, upload reservations, and rate counters across function instances. Monitor free allowances. The email update uses Brevo SMTP and a durable encrypted delivery queue. Brevo Free allows 300 emails per day; the app caps attempts at 280 per UTC day, including no more than 180 class notifications, to reserve recovery capacity.

Email is enabled on the production website. In the earlier email release, real password-reset and notification messages reached Gmail's inbox; verification reached Spam. The active one-minute worker checks the three-minute teacher-reminder window. Its automatic run returned HTTP 200, with no reminder due in that run. New reminder/daily mail is covered by fake-transport tests, not a new real-inbox test. See [EMAIL-SETUP.md](EMAIL-SETUP.md).

## Security and validation

The owner-run `schema/password-support-postgres.sql` migration is applied as `classnest_admin_password_support`. Its operational request table has RLS, server-only CRUD, and no browser-role/PUBLIC grants; the Supabase security advisor returned zero findings. SQLite initializes `schema/password-support-sqlite.sql` automatically. The server uses the new `password-support.js` module without runtime PostgreSQL DDL, additional hosting services, or a WhatsApp API credential. The 147-test suite includes generic acknowledgements/throttling, independent verification, administrator reauthentication, stale sessions/passwords, replay rejection, temporary-password expiry/forced change, portable hash preservation, approval boundaries, and frontend secret clearing.

Security includes asynchronous scrypt hashing, random HttpOnly sessions, secure production cookies, server-side roles, host/origin checks, account and request throttling, escaped text, bounded content, and security headers. Existing passwords remain valid and stored hashes upgrade on successful sign-in. Sessions rotate and are capped at ten per account. Registration returns a generic response; sign in afterward and wait for approval.

Attachments are checked by file signatures, UTF-8 validation, and bounded Office ZIP structure checks. Notice photo type/dimension headers use the pinned `image-size` 2.1.0 dependency from the lockfile. Header inspection does not fully decode every photo or provide antivirus scanning. Cloud uploads enter private staging paths and move before validation; download URLs expire quickly. Text is capped at 64 MiB and record counts are bounded. See [SECURITY-REVIEW.md](SECURITY-REVIEW.md).
