# Classnest

A class hub for Pokhara University School of Engineering. Starts at Semester 3 and stays editable as your class progresses. This is an independent student workspace.

The complete website source lives in the [`classnest/` folder of boce-chat](https://github.com/prince11ydv-maker/boce-chat/tree/main/classnest). Use this folder as the application root. Hosting and configuration are documented separately in [HOSTING.md](HOSTING.md).

The mobile and student semester-lock update is live at **https://pusoe.vercel.app**. It passed all 108 website tests, local phone-layout/account-scope checks, and production source/content checks. The live installation guide and APK link were verified in the browser. A signed, non-debuggable Android 1.0.0 APK is built and verified; Android URL-policy checks passed 57 cases. See [MOBILE.md](MOBILE.md) for the APK, free Android/iPhone home-screen installation, and the device-testing boundary, and [DEPLOYMENT.md](DEPLOYMENT.md) for release evidence. Existing accounts, the public class content, and the routine were preserved; the automatic reminder worker returned 200 after deployment.

The earlier notice attachment/direct-alert release passed 88 tests and its production checks. Its local photo/PDF and student alert workflows were verified without publishing production QA notices or sending notice emails. That earlier evidence remains scoped to its release below.

Earlier semester, routine, note-preview, email, and HTML-import verification remains recorded by release in [DEPLOYMENT.md](DEPLOYMENT.md). Older test and inbox-delivery evidence is not a claim that the new reminder workflow has reached a real inbox.

The primary address is **https://pusoe.vercel.app**. The previous address, https://classnest-pu.vercel.app, redirects to it with page paths, queries, and email-link fragments preserved. Existing accounts and passwords stay the same. Sign in once on the new address because browser sessions belong to each hostname. ## Open locally

Install Node.js 24 LTS. Double-click START-WEBSITE.cmd and open http://localhost:3000, or run:

```powershell
npm.cmd ci
npm.cmd start
```

Keep the terminal open. A new installation offers **Set up workspace** to create an owner account. No default password is shipped. Existing installations retain accounts and data; preserve their data/ directory.

## Everyday use

- **Mobile app:** install Classnest from its website on Android or iPhone, or use the signed Android APK in [MOBILE.md](MOBILE.md). An internet connection is needed for class content. Existing in-app and opted-in email alerts remain; phone push notifications are not configured.
- **Student semester lock:** signed-in student accounts stay in the administrator-assigned semester. The selector is disabled, and server checks reject cross-semester requests, files, posting, and edits. Approved teachers/admins retain their semester controls. Public visitor reading remains available under the existing policy; this account restriction does not make public notes private.
- **Appearance:** choose **Light**, **Dark**, or **System**. System follows your device's appearance and responds when it changes. Your choice is saved in this browser and stays in sync across its Classnest tabs.
- **Nepal clock:** the homepage shows the current time, including seconds, above its date. Both use Asia/Kathmandu; the clock does not announce every second to screen readers.
- **Student / Teacher / Admin sign-in:** choose the matching portal. Students choose their current semester; teacher applicants can check one or more teaching semesters. Both account types wait for administrator approval. Choosing Teacher or checking semesters never grants teacher permission by itself. Existing accounts and passwords are retained; owners use the Admin portal.
- **Teacher semester profile:** open **Teacher dashboard** and choose **Choose semesters** or **Choose my semesters** to save one or more teaching semesters. These choices organize the overview; they do not approve the account, change its primary membership semester, create classes, or grant private discussion access. Existing teachers without saved choices start from their primary semester. Administrator-assigned classes remain visible even when their semester is not selected in the profile.
- **Teacher dashboard:** approved teachers see their own classes today, unanswered upcoming classes, the next 48 hours, weekly assignments, and shared notes. Use **All my semesters** or an individual semester to focus the view. Class scope combines saved choices with actual assignments; the notes panel shows only that teacher's contributions, including notes from other semesters. The latest 200 matching note records are listed, with a notice when more exist. **Share notes** lets the teacher choose a subject in the intended semester; opening an existing note for editing loads that note's semester and text.
- **Teacher setup:** approve legitimate teacher requests in Manage workspace, then open **Teaching & my notes → Teacher timetable → Assign a class**. Choose the teacher, subject, weekday, 24-hour Nepal start/end times, and optional room. The imported weekly PDF grid does not identify teacher accounts, so reminders need these explicit assignments. No teacher accounts, addresses, or mappings are invented.
- **Daily timetable:** it appears before the weekly class routine. Administrators choose a date and publish structured subject/teacher/time/room rows, or prefill from that day's teacher assignments. Publishing an empty day marks it as having no classes. A published daily plan replaces weekly teacher assignments for that date and creates account alerts for approved recipients in that semester. Dates can be viewed from seven days ago through thirty days ahead; daily plans and class occurrences are retained for 35 days.
- **Teacher reminders and replies:** assigned teachers receive an account reminder targeted three minutes before class. Replies open 24 hours before class and close when it ends. Choose **Coming** with **1–5**, **5–10**, or **10+ minutes**, or **Not coming** with a reason. The public daily board shows attendance status; absence explanations stay in authorized teacher/admin views and private class notifications. A minute-by-minute worker checks reminders; email/provider delays can move actual delivery past the target time.
- **Notifications:** the top notification button lists notes, notices, daily plans, and teacher updates for approved accounts. Students receive their own semester's updates; teachers receive updates for their primary or actually assigned semesters. Publishing a notice creates its account alerts in the same transaction, excluding the author. **Open update** opens that notice directly in the correct semester. Alerts refresh about every 60 seconds while the website is open. This release does not configure operating-system push notifications. Email copies require verification and opt-in; teacher reminder emails have their own preference.
- **Manage workspace → Edit name & current semester:** choose the default semester visitors see. Existing semesters retain folders and notes. Visitors and approved teachers/admins can use the browsing dropdown; signed-in students remain in their assigned semester. Browsing never changes account membership.
- **Homepage → Class routine / Exam routine:** administrators can create or edit either table for the selected semester. Manage workspace has the same editor shortcuts. Add or remove rows and columns, edit headings and cells, then choose **Publish routine**. Each table allows up to 12 columns, 40 rows, and 160 characters per cell; headings and titles allow 80 characters. Changes appear publicly after saving. No exam entries are supplied: the exam section stays empty until you publish a routine. Clear rows and publish to make it empty again.
- **Routine edits:** if another administrator tab has saved a newer revision, the server rejects an outdated save. Your draft stays in the editor; choose **Discard draft & load published version** when you are ready to reload it.
- **Import a table:** in either routine editor, open **Import HTML table**, paste your `<table>…</table>` code, and choose **Preview table**. Select a table when the code contains several, and turn off the first-row heading option if needed. **Use this table in draft** replaces the editable headings and rows; the title stays unchanged. Check the grid and choose **Publish routine** to show it on the homepage. Merged cells are expanded by repeating their text. Only plain cell text is kept; scripts, links, and styling are discarded. HTML input is limited to 256 KiB and the usual routine size limits apply.
- **Subject library → New subject:** create folders with course codes, descriptions, and colors. Admins can edit or delete folders; deleting a folder also removes its notes and attachments after confirmation.
- **Share a note:** approved students can contribute in their assigned semester; approved teachers/admins retain their existing semester access. Write text or attach PDF, DOCX, PPTX, XLSX, text, Markdown, or images. Approved teacher notes publish immediately. Maximum 20 MiB per file, with 700 MiB shared across note and notice attachments. Visitors can read and download public notes; signed-in students receive their assigned semester's library. Admins and authors can delete notes within their current access. **My notes** provides a contribution panel; authors edit their own title, subject, and text, and admins can edit any note. Editing retains the existing attachment.
- **View a note:** choose **View** or open its title to preview PDF, PNG/JPG/WebP, text, or Markdown attachments inside Classnest. PDF previews include pages, zoom, and a page-text option. Long text previews show the first 1 MiB. Office files and unsupported previews retain the download option. PDF.js assets are served by Classnest; no Google/Microsoft viewer or file-sharing link is used.
- **Notice board:** administrators post, pin, and delete notices. A notice can contain text, one PDF/photo attachment, or both; its title is required. Attachments can be up to 20 MiB and share the workspace's 700 MiB file capacity with notes. Supported notice formats are PDF, JPG/JPEG, PNG, WebP, GIF, BMP, AVIF, HEIC/HEIF, and TIF/TIFF. Choose **View** or **Download**. A direct notice link focuses that card and offers **Back to all notices**.
- **Notice photos and previews:** originals can be up to 100 megapixels and 30,000 pixels per side. Supported browser-native photo previews are limited to 16 megapixels and 12,000 pixels per side. HEIC/HEIF/TIFF and larger photos keep a download option. PDF previews use the existing in-app page/zoom controls. The website does not send documents to an outside viewer.
- **Schedule & deadlines:** admins add classes, exams, events, and deadlines in Nepal time. Anyone can export an event to a calendar.
- **Join your class:** choose your current semester before entering your name, email, and password. Registration requires a valid semester. New accounts wait for administrator approval.
- **Discussions:** approved members can read, start, and reply to discussions only in their assigned account semester. The discussion page opens that semester automatically. Administrators can moderate any semester; an author can delete their own discussions while they have access to that semester. Anonymous public note reading remains available; signed-in students stay in their assigned library.
- **Class members:** approve, revoke, or block posting access and update each account's semester. Check the assignment before approving a student. Existing accounts are assigned the current workspace semester during this update: Semester 3 for this workspace. Existing passwords, sessions, and shared content are preserved.
- **Account:** view your primary assigned semester. Ask an administrator to correct it or advance it when your class progresses. A teacher's saved teaching semesters are separate profile choices. The public semester selector, teacher overview filter, and email preferences do not change membership. Email verification confirms mailbox ownership; administrators still approve classmates and teachers they recognize.
- **Saved notes:** hearts bookmark notes in the current browser. Bookmarks do not sync between devices.
- **Account → Change password:** change your password and sign out other sessions. Do not share administrator credentials.
- **Sign in → Forgot password?:** request a private, single-use reset link. It expires after 30 minutes; completing the reset signs out old sessions and returns you to ordinary sign-in.
- **Account → Email preferences:** verify your email and opt in to new notes, notices, or schedule/daily/attendance updates. Student emails follow the account's assigned semester. Approved teachers can separately enable their teaching-reminder emails. All categories start off; approval and verified email are required and checked again before delivery. Each notification includes a link to stop emails without signing in.
- **Help & FAQs:** sixteen answers cover teacher/student accounts, daily plans, notifications, routines, note previews, public notes, registration, private discussions, semester changes, uploads, email, themes, and browser bookmarks. The footer includes Prince Kumar Yadav's copyright and contact email, plus the FAQ link, on desktop and mobile.

Create any subjects and semesters you need. No guessed syllabus, fabricated course notes, or university notices are shipped.

## Backups and recovery

**Manage workspace → Download database backup** exports a local SQLite snapshot or cloud portable JSON. It includes personal information and password hashes: keep it private. Attachments are separate. Copy local data/uploads/ or back up the private Supabase bucket, and keep copies off the server.

Current portable-v1 exports contain fifteen durable tables, adding notice attachment metadata to routines, teacher assignments, daily plans, class occurrences, and teacher semester-profile choices. Older nine-, ten-, thirteen-, and fourteen-table exports are accepted and gain empty optional collections; old user records default to student account type unless their role is teacher. Account IDs and password hashes are preserved. Portable exports exclude sessions, app-notification inboxes, notice upload markers, email tokens, email preferences, queue contents, and secrets. They contain attachment metadata, not file bytes: back up both note and notice files separately. Imports require an empty target and reject a filename shared by a note and a notice. Class occurrences include teacher replies and reasons, so keep backups private.

To restore SQLite, stop the application first, preserve the current directory, and restore the snapshot as data/classnest.sqlite with matching uploads. Do not reuse stale WAL/SHM files from a different database. Never replace a running database. Cloud imports refuse occupied targets; use a new database for recovery and verify it before switching the runtime connection.

Local SQLite mode supports one server. PostgreSQL/Supabase mode uses shared locks, sessions, upload reservations, and rate counters across function instances. Monitor free allowances. The email update uses Brevo SMTP and a durable encrypted delivery queue. Brevo Free allows 300 emails per day; the app caps attempts at 280 per UTC day, including no more than 180 class notifications, to reserve recovery capacity.

Email is enabled on the production website. In the earlier email release, real password-reset and notification messages reached Gmail's inbox; verification reached Spam. The active one-minute worker checks the three-minute teacher-reminder window. Its automatic run returned HTTP 200, with no reminder due in that run. New reminder/daily mail is covered by fake-transport tests, not a new real-inbox test. See [EMAIL-SETUP.md](EMAIL-SETUP.md).

## Security and validation

Security includes asynchronous scrypt hashing, random HttpOnly sessions, secure production cookies, server-side roles, host/origin checks, account and request throttling, escaped text, bounded content, and security headers. Existing passwords remain valid and stored hashes upgrade on successful sign-in. Sessions rotate and are capped at ten per account. Registration returns a generic response; sign in afterward and wait for approval.

Attachments are checked by file signatures, UTF-8 validation, and bounded Office ZIP structure checks. Notice photo type/dimension headers use the pinned `image-size` 2.1.0 dependency from the lockfile. Header inspection does not fully decode every photo or provide antivirus scanning. Cloud uploads enter private staging paths and move before validation; download URLs expire quickly. Text is capped at 64 MiB and record counts are bounded. See [SECURITY-REVIEW.md](SECURITY-REVIEW.md).
